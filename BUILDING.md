# Сборка glitchOS 0.5.0 для OnePlus 6T

Дерево Android: `/home/cfifboom/android/lineage`. Рабочие исходники помощницы:
`/home/cfifboom/android/glitchos-development`. Результат: `../out/fajita`.
База — LineageOS 22.2 / Android 15, `lineage_fajita-userdebug`, release `bp1a`.
Действующие ключи находятся в `vendor/lineage-priv/keys`; сохранять их.

## Подготовка существующего дерева

Синхронизация репозиториев, очистка `out`, генерация ключей и сброс телефона
для этих изменений не нужны. В `packages/apps/Trebuchet` применяется
`patches/lineage-22.2-sole-home.patch`: HOME остаётся у glitchOS,
Quickstep предоставляет список недавних приложений. Патч включает обработку
отсутствия собственного HOME в `OverviewComponentObserver`.

В `build/soong` применяется `patches/soong-optional-memory-limit.patch`.
Он передаёт `SOONG_GOMEMLIMIT` и `SOONG_GOGC` процессу Soong через его
изолированное окружение. Обычный экспорт `GOMEMLIMIT` туда не проходит.
Без этих двух переменных поведение сборщика прежнее.

Перед первым применением каждого патча использовать `git apply --check`.
Если уже применён — `git apply --reverse --check`; не накладывать повторно.
В текущем рабочем дереве оба патча уже применены.

## Сборка

```bash
cd /home/cfifboom/android/glitchos-development
bash tools/Build-Rom.sh modules
```

Скрипт проверяет патчи, подключает `vendor/contour` с резервной копией,
собирает `ContourHome` и **TrebuchetQuickStep**. Обычный модуль `Trebuchet`
не заменяет Quickstep и для этой прошивки не подходит. Изменённые файлы получают
свежую дату в дереве Android: сохранение старой даты из архива может оставить
у Ninja устаревший манифест. Неизменённые файлы и product.mk не переписываются.
Версия Clang для ядра берётся штатным `get_clang_version.py` и передаётся через
`LLVM_AOSP_PREBUILTS_VERSION`, как в Lineage envsetup. Наличие компилятора
проверяется до сборки: без этой переменной модули могли собраться, а ядро — нет.

Для полной OTA после проверки модулей:

```bash
bash tools/Build-Rom.sh ota
```

Используются прежние ключи и Updater, имя сборки `glitchOS-0.5.0` с датой и
временем. Оба режима собирают файлы на ПК; на телефон ничего не отправляют.
Перед полной сборкой сохранять предыдущий target-files вне `out`.
Для 0.3 он сохранён в `G:\glitchOS\baseline-fajita\target-files-0.3`;
ZIP проверен по CRC, SHA-256 записан рядом. Его соответствие базовому
payload для инкрементальной OTA ещё требуется проверить отдельно.

Среда WSL: 16 GiB RAM, 32 GiB swap, 8 CPU. Скрипт использует `-j2`,
`SOONG_GOMEMLIMIT=10GiB`, `SOONG_GOGC=40`. Размер heap — мягкий предел Go,
не ограничение всего RSS. Холодное чтение дерева с диска G: может занимать
заметное время. Проверять физическое место через `df -h /mnt/g`;
свободное место виртуального ext4 не равно остатку на G:.

## Проверка и установка

- Проверить подписи APK и OTA существующим сертификатом, метаданные устройства,
  новый timestamp, отсутствие wipe/downgrade, SHA-256 и содержимое пакета.
  В дереве уже собран официальный `check_ota_package_signature`; при добавленном
  `out/fajita/host/linux-x86/bin` в PATH он проверяет весь ZIP и A/B payload:
  `check_ota_package_signature vendor/lineage-priv/keys/testkey.x509.pem /путь/OTA.zip`.
  Проверка только сертификата внутри ZIP не заменяет эту проверку подписи.
- Для отдельной проверки APK использовать замену `adb install -r` с совпадающей
  подписью. Не удалять данные приложений. Тестовый `app.contouros.checks`
  не включать в ROM и удалить после проверки.
- Проверить HOME, Recents, жесты, три кнопки, размеры и сохранение плиток,
  клавиатуру в диалоге, будильник и перезагрузку.
- Полную OTA можно импортировать локально в существующем Updater. Он проверяет
  подпись перед установкой; публикация в GitHub для локальной проверки не нужна.
- Проверять подключение именно экспериментального OnePlus перед каждым
  действием. Перед установкой предупредить о перезагрузке; во время записи
  не выключать телефон. При установке через USB также не отключать ПК/кабель.

Сборка требует включённого ПК без сна. После её завершения и проверки
загрузки телефона сообщать, остались ли фоновые процессы и можно ли выключать ПК.
Простое переключение A/B-слота не считать универсальным откатом.

## Откат исходников

`Configure-Home.py` выводит точный путь резервной копии. Восстановление:

```bash
python3 tools/Configure-Home.py --restore /точный/путь/к/копии
```

Скрипт проверяет контрольные суммы и не затирает более поздние изменения.
Это откат исходников, а не телефона. Патчи Trebuchet и Soong снимаются отдельно
через `git apply --reverse` после проверки. Исторический патч SetupWizard
не применять: текущему замыслу знакомства он не соответствует.

## Временные APK поверх системы

После OTA APK из `/data/app` с равным versionCode может продолжить перекрывать
системный APK. Перед возвратом на встроенную копию сравнить versionCode,
сертификат и содержимое **уже установленной новой ROM**. В Android 15 удаление
обновления системного приложения сохраняет данные при равной или более новой
системной версии и том же appId. При старой системной версии код PackageManager
снимает KEEP_DATA даже при `-k`; поэтому до OTA эту операцию для ContourHome
не выполнять. После возврата отдельно проверить сохранённую раскладку и историю.
